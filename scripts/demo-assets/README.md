## 处理

| 步骤 | 说明 |
|---|---|
| 下载 | `images.pexels.com/.../30473642.jpeg?w=1200`（1200×1800，原图 2:3 竖构图） |
| 裁切 | 居中裁成 **3:2**（1200×800）—— 保留孤树与雪坡，去掉过多天空与前景 |
| 缩放 | 到 **520×347**（见下：**这是体积预算的一部分**） |
| 去元数据 | 用 Pillow 重新编码，**exif 全部丢掉**（相机 / GPS 不该跟着动图一起公开） |
| 体积 | JPEG q86 / progressive ≈ **50 KB** |

## 为什么是 520 宽（而不是塞满正文栏）

演示动图要压在 **~160 KB** 以内（README 首屏，越小越好）。GIF 的体积几乎全在"有没有大片细节"：
同一张图 640 宽时成片 183 KB，520 宽时 **160 KB**，而照片在画面里仍然占正文栏的 80% 以上。
⚠️ 想换成别的图，先按这个尺寸做一版、跑 `capture-demo-gif.mjs` 看体积再决定；**平滑渐变多的图
（天空／雾）最吃亏**：96 色下要么出阶梯，要么为抖动付字节。

## 为什么放在仓库里

录制脚本（`scripts/capture-demo.mjs`）每次都要读它 —— 不入库的话，换台机器就重录不出来。
