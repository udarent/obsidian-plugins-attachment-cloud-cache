# Attachment Cloud Cache（附件云端缓存）

[English](./README.md) · **简体中文**

把笔记里的附件上传到**你自己的** S3 兼容存储，同时在本地留一份缓存副本 —— 断网时图片照样能显示。

> **状态：1.0.0。**
> **能用的：** 粘贴/拖入即上传、离线渲染、按需补回缺失副本、可选的站外图片缓存与缓存上限、四条维护命令。
> **已验证：** 上传/下载完整回环已在真实 MinIO 上被证实 —— 见下文「已验证到什么程度」。
> **还没验证的：** iOS 从未运行过；Android 也没在真机上跑过。

## 为什么用它

附件这件事通常被两个插件分着解决，各自留一个绕不过去的缺口：**上传类**把笔记改成远端地址、
往往还删掉本地文件，于是断网就看不到图；**「本地化」类**要把远端图片下载回 vault，
于是你必须先联网至少一次。

本插件两件都做：先上传，再把本地文件**留作缓存**。笔记指向你的存储（可迁移、可分享、vault 小），
渲染用本地副本（没有网络也能显示，离线时**零**远端请求）。

## 功能

- **S3 兼容存储**：Cloudflare R2、AWS S3、MinIO、Backblaze B2，或任何 S3 兼容端点
- **粘贴或拖入即上传**，并把笔记里的链接改写成指向你的存储
- **断网也能看图**：渲染时换成本地副本，离线时零远端请求
- **默认按内容寻址**（`{hash}.{ext}`）：同一张图只存一份，粘两次不会重复上传
- **不会丢图**：上传失败就把文件留在附件目录、插入一条能用的本地链接，并说明原因
- **不会覆盖同名文件**：`a.png` 会自动变成 `a 1.png`
- **可选的站外图片缓存**（默认关闭）：同一站点只问一次，你同意才下载
- **可选的缓存上限**（默认关闭）：超限时按最近最少使用在后台清理，空间立刻释放
- **四条维护命令**：查看缓存占用、自检并修复本地副本索引、清理未使用的缓存文件、上传已存在的附件
- **桌面端与移动端**都支持

## 安装

需要 Obsidian **1.13.0** 或更新（桌面端与移动端）。下限由声明式设置 API 决定 —— 它让设置项能被
Obsidian 的全局搜索搜到。代价是最近几个月没更新过 Obsidian 的用户装不了。

1. 构建或下载 `main.js`、`manifest.json`、`styles.css`
2. 放进 `<vault>/.obsidian/plugins/attachment-cloud-cache/`
   ⚠️ 目录名必须与插件 id 完全一致 —— `attachment-cloud-cache`
3. 在 **设置 → 第三方插件 → 已安装插件** 里启用

## 配置

打开 **设置 → Attachment Cloud Cache**，然后：

1. 填 **服务地址**、**存储桶**、**区域**
2. **公开访问前缀**可以留空：留空就用对象地址（`服务地址/存储桶/键`），那要求存储桶允许匿名读取。
   图片走 CDN 或自定义域名时把前缀填在这里 —— 输入框里会显示「留空会用什么地址」
3. 填 **访问密钥 ID**（普通输入框，含大写是正常的），再在它下面那一格填 **秘密访问密钥**
4. 点 **测试连接** —— 它先向你的桶发一次签名请求，再**不带任何凭据**打开一次「你笔记里会写的那条
   链接」，告诉你别人打不打得开

## 需要注意的

- **拖放文件的链接插在光标处，不是指针落点。** 原生 Obsidian 用指针位置，但公开 API 里没有
  「指针坐标 → 编辑器位置」的映射（要拿到它就得依赖未公开的内部对象）。拖放时若光标在别处，
  链接就落在别处。这是有意取舍。
- **改了存储地址之后，「新设备」上认不出老链接。** 判断「这张图是我们的」依赖当前设置加本地副本
  索引；换了域名或清了公开访问前缀、而本地又没有副本时，那些老链接会被当成站外图片 ——
  照常在线显示，但离线不显示，也不会被自动下载。同样是有意的：另一条路是去猜别人的 URL。
- **「不留本地副本」这一档会让断网时看不到图。** 三档里只有它与「离线可用」冲突；默认档是
  「移入缓存目录（离线可用）」。
- **缓存目录可以随时整体删除。** 这是设计的一部分：再看那张图时按需重建。想清空间就直接删。

## 隐私与安全

- **默认情况下它只连你自己的存储。** 插件只把你选择上传的附件发到你配置的服务地址。不含遥测、
  统计与广告。
- **有一个可选功能会访问其它站点，而且只有你打开它时才会。** 设置里的「缓存站外图片」**默认关闭**。
  打开后，打开一篇含站外图片的笔记会**按站点询问一次**：你选「缓存并记住该站点」时，插件会
  **直接向那个站点**请求那张图，再上传到你的存储并改写链接；你选过「此站点不再询问」的站点永不请求。
  请求里除图片地址本身不带任何其它内容。功能关闭时，插件除你的存储外不向任何站点发起请求。
- **不碰 vault 之外的文件。** 读写的所有内容都在你的 vault 内。
- **秘密访问密钥存在操作系统钥匙串里**，绝不写进 `data.json`。**访问密钥 ID 会写进 `data.json`** ——
  它是标识符而不是秘密（它本身就是被签名请求的一部分，也会出现在服务端日志里），而且 Obsidian 的
  钥匙串只接受小写 ID，访问密钥 ID 常规就带大写。单独拿到 ID 什么都签不了。

## 已验证到什么程度

- **自动化测试**：签名与路径推导、设置合并、缓存索引、上传链路（字节一致、恰好 1 次 PUT、0 次 GET）、
  粘贴/拖放判定、清理命令的安全性质都有测试。并且做**变异验证**：把每条规则故意改坏，确认测试会因
  *那条规则自己的原因*失败 —— 不会失败的测试等于没有测试。
- **真实宿主**：用真实构建产物在真实 Obsidian 里跑一遍 —— 插件加载、四条命令注册、设置页渲染、
  实时预览的图片替换生效，且不碰站外图片。
- **真实服务端**：在真实 MinIO 上，两个方向都已被证实 —— 粘贴一张图会上传，且对象 key 由脚本用
  `node:crypto` 从字节**独立重算**、与写进笔记的一致；链接**匿名**能打开（不带凭据，也就是别人看到的样子）；
  读回的字节与本地副本逐字节相同；渲染出的 `<img>` 指向本地副本，而不是远端 URL。下载路径由更早几轮
  在同一实例上的运行覆盖。可用 `npm run verify:real-storage` 复现（它会往你的桶里上传一个对象）。
- **没验证的**：iOS 从未运行过（这台机器上做不到）；Android 也没在真机上跑过。代码避开了已知在那里
  缺失的 API、并在可选 API 不存在时降级，但那是推理，不是证据。含非 ASCII 字符的对象 key 也还没在
  真实服务商上跑过（编码本身有测试覆盖）。

## 开发

```bash
npm install
npm run dev          # watch 构建
npm run check        # 构建 + lint + manifest + 各类护栏 + 测试
npm run test:unit    # 只跑测试
npm run mutate       # 变异验证：每条规则的断言是否真的有牙齿
```

测试跑在 Node 上、不用测试框架：该用真实的地方就用真实 HTTP 服务与真实文件系统，而不是 mock。
`npm run check` 还挂着几条静态护栏，其中一条专门守着「两份 README 不许单边漂移」。
